# Workload analysis stays visible

Workload is an automatic overview of the complete import. Its normal flow is:

1. Economics, date span, responses, known tokens and pricing coverage.
2. Projects: distribution and local project inspection.
3. Model mix: horizontal shares and current API contribution from existing exact-route receipts, followed by token composition.
4. Recorded demand: daily histogram, busiest day, hours and weekdays.
5. Session shape: largest sessions, concentration, peak windows and inspection.
6. Capacity: compact account/cycle-scoped burden and a focused timeline action.

The five analysis sections use numbered headings. None of their charts is inside Methodology. Calls/tokens and timezone controls change the presentation without rerunning API pricing. Full-import analytics remain full-import analytics when a separate billing cycle is configured.

The bottom Methodology, assumptions & evidence disclosure holds pricing receipts, cache assumptions, coverage, parser diagnostics, catalog identity and limitations. Optional sharing and older scoped replay tools have their own separate disclosure. Duplicate model tables, highlight cards and repeated default disclaimers were removed.

No parser, optimizer, billing or capacity semantics changed. Browser coverage checks visibility with Methodology closed, narrative order, model contribution, measure controls, keyboard, accessibility, themes and mobile layout. Private full-import and completed-cycle screenshots remain local review artifacts.
