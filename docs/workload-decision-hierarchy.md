# Workload decision hierarchy

Workload opens with account and period setup until history coverage and same-period billing facts are confirmed. Configured reviews collapse those controls into an editable review bar. Incomplete pricing remains explicit and never produces a whole-workload ratio.

The default page presents:

1. Confirmed spend, current published API equivalent, approximate API-equivalent-to-spend ratio, response/token/pricing coverage, and observed episode count.
2. Project distribution, useful workload highlights, and compact model economics.
3. Capacity episodes, blocked attempts, affected days, recorded continuity elsewhere, and an expandable interruption timeline.
4. A single **Methodology, assumptions & evidence** disclosure for conclusions, pricing receipts, cache scenarios, integrity, raw capacity evidence, provenance, catalog details, and the existing analytical tools.

**Why a range?** explains the unchanged cache-write scenarios beside the API result. Ratios use the exact calculated bounds divided by confirmed spend, rounded for display. They are unavailable for partial reviews or zero spend, and are not savings or replacement claims.

Projects and highlights reuse the saved import profile. When that profile includes work outside the selected account or period, the section explicitly says **Full saved import, including work outside the review**. Model economics and the economic hero remain scoped to the review. Highlight links open their detailed evidence before navigating.

Billing edits, history confirmation, local impact annotations, sharing exclusions, response deduplication and capacity grouping retain their existing behavior. Compare consumes the same cached result. No pricing, catalog, import or capacity methodology changed.

Browser coverage checks configured and incomplete layouts, period changes, keyboard editing, hidden evidence, range disclosure, themes, mobile overflow, accessibility, and the existing D2–D6 semantics. Private validation history stays outside source control and is loaded only into local browser storage.
